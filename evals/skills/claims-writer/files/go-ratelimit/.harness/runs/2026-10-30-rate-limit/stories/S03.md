## What

Limit each API client to a fixed number of requests per time window.

## Request

> Clients are hammering the API. Cap each client at a configurable number of requests per window and answer
> 429 once they are over it. The limiter must not slow the hot path: p99 under 5 ms in staging.

## Acceptance criteria

- AC-1: A client may make up to the configured limit of requests in one window; the next request is refused.
- AC-2: A refused request is answered with HTTP status 429.
- AC-3: With the limiter enabled, p99 latency of the API in staging stays under 5 ms.

## Tests expected

Unit tests for AC-1 and AC-2. AC-3 is measured in staging.

## Out of scope

Distributed limits across several API instances.
