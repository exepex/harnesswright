## What

Limit each API client to a fixed number of requests per time window.

## Request

> Clients are hammering the API. Cap each client at a configurable number of requests per window and answer
> 429 once they are over it. The limiter must not slow the hot path: p99 under 5 ms in staging.

## Acceptance criteria

### AC-1

- **Criterion:** A client may make up to the configured limit of requests in one window; the next request is refused.
- **Test types:** [unit]

### AC-2

- **Criterion:** A refused request is answered with HTTP status 429.
- **Test types:** [unit]

## Targets

### NFR-1

- **Measures:** p99 latency of API requests on staging while the limiter is on
- **State:** exact
- **Number or range:** under 5 ms
- **Test types:** [performance]

## Gaps

None.

## Out of scope

- Distributed limits across several API instances.
